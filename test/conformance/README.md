# zap-sh conformance suite

This directory pins the **byte-for-byte** output of `zap-sh init` (the bash
oracle) so that a second implementation — the JavaScript generator added in a
later milestone — can be verified against the exact same inputs and outputs.
The contract itself is documented in [`SPEC.md`](../../SPEC.md).

## Layout

```
test/conformance/
├── lib.sh              # shared helpers: fixture -> `zap-sh init` args, generate
├── gen-expected.sh     # regenerates expected/*.sh from the fixtures (oracle)
├── fixtures/*.json     # inputs: one generation case per file
└── expected/*.sh       # golden outputs (ground truth, generated by the oracle)
```

The runner is [`../test-conformance.sh`](../test-conformance.sh); it is listed in
[`../tests.txt`](../tests.txt) and runs as part of `make test`.

## Fixture format

Each fixture is a JSON object:

```json
{
  "name": "basic-mit-full",
  "template": "basic",
  "project": "deploy",
  "year": "2025",
  "license": "mit",
  "variables": {
    "author": "Alice",
    "email": "alice@corp.io",
    "version": "2.3.1",
    "detail": "Deploy helper",
    "description": "Deploys things to places"
  }
}
```

| Field | Required | Meaning |
|-------|----------|---------|
| `name` | yes | Fixture id; the golden file is `expected/<name>.sh`. |
| `template` | yes | `basic` or `enhanced`. |
| `project` | yes | Project name (positional arg); becomes `{{app}}`. |
| `year` | yes | Pins `{{year}}` (see determinism note below). |
| `license` | no | License code (`mit`, `apache`, `gpl`). Omit for the no-license path. |
| `variables` | no | `--key=value` flags; **key order is preserved and significant**. |

The runner turns a fixture into `zap-sh init <project> -t <template>
--year=<year> [--license=<code>] [--<k>=<v> ...]` (see `conf_build_args` in
`lib.sh`). Output path never affects the generated bytes, so it is supplied by
the tooling, not the fixture.

## Determinism

`year` is the only clock-derived input. `--year` pins every `{{year}}` that
appears in the template or license text (all real occurrences). The one thing it
does **not** pin is a `{{year}}` token embedded inside a *field value* — that is
resolved by the always-present default `year=$(date +%Y)` and would drift with
the wall clock. Fixtures therefore never put `{{year}}` inside a value; the
substitution-ordering behavior is locked with `{{version}}`/`{{author}}` instead
(`basic-placeholder-literal`). See `SPEC.md` §6.

## Adding or changing a fixture

1. Add/edit a JSON file under `fixtures/`.
2. Regenerate the golden files from the oracle:
   ```bash
   test/conformance/gen-expected.sh
   ```
3. Review the diff in `expected/` and run `make test`.

Regenerate golden files **only** for a deliberate, spec-approved change to
generation behavior (and bump `SPEC-VERSION` in `SPEC.md` when the observable
contract changes). A regression in `zap-sh` must fail the suite, not be papered
over by regenerating.

## Requirements

`jq` is required (present on GitHub-hosted runners and most dev machines). If
`jq` is missing the runner prints a visible skip rather than failing.
